# النسخ الاحتياطي والاستعادة

توجد الميزة لمالك المتجر داخل Profile ثم Backup & recovery. تُنشأ النسخ يدويًا عبر الإنترنت داخل `stores/{storeCode}/backups/{backupId}`، مع سجلات المنتجات والمبيعات في مجموعتين فرعيتين وإعدادات اسم المتجر وBenefitPay في وثيقة النسخة. لا تُنسخ كلمات المرور أو حسابات المستخدمين أو المفاتيح أو بيانات المصادقة.

تظهر النسخ المكتملة فقط وتاريخ آخر نسخة ناجحة. لا تصبح النسخة مكتملة إلا بعد تأكيد جميع كتاباتها. الانقطاع قد يترك نسخة غير مكتملة ومخفية؛ إعادة المحاولة تنشئ نسخة جديدة. لا توجد جدولة تلقائية أو حذف تلقائي للنسخ القديمة، وقد تزيد قراءات وكتابات وتخزين Firestore بحسب حجم البيانات. هذه نسخ داخل نفس مشروع Firebase، وليست حماية مستقلة من حذف المشروع أو فقدان حسابه.

يجب إيقاف البيع ومزامنة كل أجهزة المتجر أثناء النسخ والاستعادة. التطبيق يفحص سلة هذا الجهاز والمبيعات المعلقة للمستخدم الحالي على هذا الجهاز فقط. لا يكتشف العمليات غير المتزامنة على أجهزة أخرى، والنسخة ليست لقطة ذرية لكل قاعدة البيانات.

الاستعادة تعرض معاينة وعدد المنتجات والمبيعات. تسترجع الوثائق الناقصة فقط بنفس معرفاتها؛ لا تعيد الدفع أو تخصم المخزون ولا تستبدل سجلات أحدث. المنتج المحذوف المسترجع يبدأ بكمية صفر ويحتاج جردًا فعليًا؛ لا تُستعاد كمية مخزون قديمة قد تكون بيعت لاحقًا. خيار استعادة اسم المتجر وإعدادات BenefitPay منفصل وصريح. افتح Profile مجددًا لتحديث الإعدادات المعروضة بعد استعادتها.

الاستعادة متعددة المعاملات وليست عملية ذرية واحدة؛ إذا انقطعت قد تكون بعض السجلات استُرجعت بالفعل. يمكن إعادة المحاولة، فهي تتخطى الوثائق الموجودة. لا تُحذف بيانات حالية ولا تُستعاد طوابير دفع قديمة.

## متطلبات تشغيل Firebase

قواعد النسخ الاحتياطي مدمجة الآن داخل ملف `firestore.rules` في جذر المشروع. تُختبر قواعد الوصول باستخدام محاكي Firestore قبل نشرها؛ تبقى حسابات المستخدمين وكلمات المرور خارج النسخ الاحتياطية.

اختبارات fake_cloud_firestore تتحقق من منطق التطبيق، لكنها لا تتحقق من القواعد الفعلية أو الاتصال أو التعارض بين أجهزة حقيقية. اختبر القواعد في Emulator Suite، ثم إنشاء نسخة واستعادتها من حساب المالك على بيئة اختبار، قبل الاعتماد على الميزة.
